1. CONTEXTE ET PROBLÉMATIQUE

 

1.1 Contexte général

Dans de nombreuses zones urbaines et périurbaines d'Afrique subsaharienne, la criminalité (vols, agressions, incivilités) constitue une menace quotidienne pour les citoyens. Les forces de l'ordre, souvent sous-dotées, ne peuvent pas être présentes partout. Les habitants manquent d'outils numériques adaptés pour se protéger, alerter leur entourage et coordonner des réponses collectives.

1.2 Problème principal

Absence d'un outil mobile simple, léger et accessible permettant à un citoyen en situation de danger de :

·     Alerter immédiatement ses proches et sa communauté

·     Signaler un incident sur une carte partagée en temps réel

·     Accéder aux numéros d'urgence même sans connexion

·     Contribuer à une base de données communautaire de sécurité

1.3 Contraintes du terrain

Contrainte

Impact sur la conception

Connexion 2G/3G limitée

App légère < 10 MB, fallback SMS, cache offline

Faible maîtrise tech des utilisateurs

UI ultra-simple, 3 actions max par écran

Risque de représailles

Mode discret, signalement anonyme, déguisement d'app

Développer une application mobile multiplateforme (Android prioritaire, iOS secondaire) permettant aux citoyens de zones à risque de se protéger mutuellement grâce à la technologie, même avec une connectivité réduite.

4.2 Architecture système

Le système repose sur une architecture 3-tiers classique optimisée pour la connectivité faible :

·     Couche Présentation : Application Flutter (Android prioritaire), UI minimaliste, cache local SQLite

·     Couche Métier : API REST Node.js, logique d'alerte, gestion des rayons géographiques, WebSockets pour le temps réel

·     Couche Données : PostgreSQL + PostGIS pour les données géospatiales, Redis pour le cache des alertes actives

Principe clé : "Offline First" — toutes les données critiques (annuaire, contacts) sont stockées localement et synchronisées dès que la connexion est disponible.

4.3 Sécurité et confidentialité

·     Chiffrement de bout en bout pour les messages d'alerte

·     Anonymisation des signalements (pseudonymes, pas de nom réel exposé)

·     Pas de vente de données — modèle économique transparent

·     Conformité RGPD et législations locales de protection des données

·     Audit de sécurité obligatoire avant le déploiement public

10.2 EPIC 1 — Alerte et SOS

 

 

US-01  |  Bouton SOS principal    [CRITIQUE — 8 pts]

Persona

P1 — Citoyen

User Story

En tant que citoyen en danger, je veux appuyer un bouton SOS afin d'alerter immédiatement mes contacts de confiance et les utilisateurs proches.

Critères d'acceptation

✓  Le bouton SOS est visible dès l'ouverture de l'app (max 1 tap)

✓  L'alerte est envoyée en moins de 30 secondes

✓  La position GPS est incluse dans l'alerte

✓  Les contacts du cercle de confiance reçoivent une notification immédiate

✓  Les utilisateurs dans un rayon de 500m sont notifiés

✓  Un accusé de réception confirme l'envoi à l'utilisateur

 

 

US-02  |  SOS discret (volume)    [HAUTE — 5 pts]

Persona

P1 — Citoyen

User Story

En tant que citoyen en danger, je veux déclencher le SOS discrètement via 3 appuis sur le bouton volume afin d'alerter sans que mon agresseur s'en aperçoive.

Critères d'acceptation

✓  L'app fonctionne en arrière-plan et détecte les 3 appuis volume

✓  Aucun son, vibration ou affichage visible lors du déclenchement discret

✓  L'alerte envoyée est identique à celle du bouton SOS normal

✓  L'utilisateur peut activer/désactiver ce mode dans les paramètres

 

 

US-03  |  Annulation alerte    [HAUTE — 3 pts]

Persona

P1 — Citoyen

User Story

En tant que citoyen, je veux annuler une alerte SOS envoyée par erreur afin d'éviter de mobiliser inutilement ma communauté.

Critères d'acceptation

✓  Un bouton "Annuler l'alerte" apparaît immédiatement après l'envoi SOS

✓  L'annulation est possible dans les 2 minutes suivant l'envoi

✓  Une notification d'annulation est envoyée à tous les destinataires

✓  L'incident annulé est marqué comme "fausse alarme" dans la carte

 

 

US-04  |  Vue responsable secteur    [HAUTE — 5 pts]

Persona

P2 — Responsable

User Story

En tant que responsable communautaire, je veux recevoir toutes les alertes SOS de mon secteur afin de coordonner une réponse rapide.

Critères d'acceptation

✓  Les alertes du secteur s'affichent en temps réel sur ma vue

✓  Je reçois une notification prioritaire (son distinct) pour chaque SOS

✓  Je peux voir le nom (ou pseudonyme) et la position de l'alerteur

✓  Je peux marquer une alerte comme "prise en charge"
